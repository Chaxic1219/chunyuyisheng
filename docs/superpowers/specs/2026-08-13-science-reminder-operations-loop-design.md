# 运营中心·科普提醒闭环升级设计

日期：2026-08-13  
状态：方案二已确认，等待原型方向选择

## 目标

把现有“生成草稿、人工发送、每日/每周计划”升级为一个可实际使用的运营闭环：运营人员能够明确选择内容依据，手工与定时任务共用同一套生成规则，并能看见待审、成功和失败状态。

## 产品结构

模块保留在“运营中心 → 科普提醒”，包含三个工作区：

1. 内容工作台：选择目标群、主题、受众和基础信息，并按需选择知识策略，生成并审核草稿。
2. 提醒计划：在同一份内容配置上增加执行周期、星期和时间；到点只生成待审草稿。
3. 运行记录：展示待审、已发送、已取消和生成失败记录，以及计划的下次执行时间。

不建设自动群发、多级审批、复杂活动编排和完整效果大盘。

## 核心流程

`内容配置 → 选择知识策略 → AI/模板生成 → 展示依据和降级状态 → 人工审核 → 立即发送或保存为计划`

手工生成和计划触发必须调用同一个生成入口。计划保存受众、基础信息、知识策略和生成方式，不再退回另一套固定模板逻辑。

## 页面设计

### 内容工作台

- 主操作为“生成科普草稿”。
- 配置项：目标群、主题、受众、基础信息、生成方式、知识策略。
- 知识策略支持“不引用”“指定引用”“自动匹配”：不引用时依靠模型通用知识；指定引用仅展示当前医生名下 `ready` 条目，最多选择三条；自动匹配由系统推荐并在审核区明确展示实际依据。
- 不引用知识时必须标注“AI 通用知识，无外部知识依据”，并继续要求人工医学审核。
- 审核区显示正文、来源、引用知识、AI 模型或降级状态、生成时间和字符数。
- 发送、编辑、取消按钮分别按实际权限显示或禁用并说明原因。

### 提醒计划

- 支持每日或每周、小时和分钟。
- 显示启停状态、目标群、内容主题、下次执行、上次结果和待审数量。
- “立即生成”仍只产生待审草稿。

### 运行记录

- 复用 `outbound_queue`，不新增通用任务系统。
- 支持按待审、已发送、失败筛选。
- 失败记录展示简短原因和重试入口。

## 数据与服务

- 扩展 `science_reminder_plans`：分钟、受众、基础信息、知识策略（`none` / `selected` / `auto`）、生成方式、上次尝试时间和上次错误。
- 知识条目在服务端验证医生归属和 `ready` 状态。
- 计划调度以北京时间执行，并对短时间停机提供有限补偿；幂等键防止同一周期重复生成。
- 继续写入 `outbound_queue`，状态仍为 `pending`；不允许自动发送。

## 错误处理

- AI 不可用时生成明确标识的模板草稿，不伪装成 AI 成功结果。
- 指定知识失效、群暂停或目标群缺少企微标识时阻止生成，并在计划上保留错误原因；不引用知识不应因知识库为空而失败。
- 发送失败回滚为待审状态，保留错误信息和尝试次数。

## 验收标准

- 可不引用知识、指定 1–3 条当前医生的已审核知识，或让系统自动匹配并展示实际依据。
- 手工与计划生成共用相同内容输入和安全约束。
- 草稿能看见依据、AI/降级状态和生成时间。
- 页面操作与创建、编辑、发送权限一致。
- 计划能看见下次执行、上次结果和待审积压。
- 短时间重启不会永久漏掉当期计划，同一周期不会重复生成。
- 所有自动任务只生成待审草稿，绝不自动发群。

## 原型约束

- 桌面运营后台，画布 1440×1024。
- 沿用左侧导航、顶部医生上下文、Element Plus 风格和医疗蓝绿色语境。
- 强调一个主要任务，不堆叠无数据依据的指标或复杂图表。
