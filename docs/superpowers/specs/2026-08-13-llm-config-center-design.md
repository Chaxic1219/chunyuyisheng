# 大模型配置中心优化设计

## 目标

将现有单一全局模型配置升级为“模型池 + 业务路由”，允许多个模型并存，并为每条 AI 业务配置主模型、备用模型和本地兜底策略。

- [模型池配置页](../../prototypes/llm-model-pool-v1.png)
- [业务路由页](../../prototypes/llm-business-routing-v1.png)

## 页面结构

大模型配置中心包含两个页签：

1. **模型配置**：左侧模型池，右侧当前模型详情。
2. **业务路由**：按业务场景配置主模型、备用模型和失败处理。

## 模型池

每个模型独立维护：

- 配置名称
- 供应商
- Base URL
- API Key（只写、脱敏展示）
- 模型标识
- 请求超时
- 启停状态
- 最近测试结果、延迟和测试时间

支持新增、复制、编辑、测试、启停和删除模型。未通过连通性测试的模型允许保存，但不能分配到新业务。已被业务引用的模型不可直接删除或停用，必须先解除引用。

## 业务路由

首期业务场景：

- AI 分诊
- Agent / 医助草稿
- 科普提醒 AI 草稿
- 小程序 AI
- 健康探针

每条业务路由包含：

- 主模型（必填）
- 备用模型（可选，不能与主模型相同）
- 失败后处理（必填）
- 启用状态

调用顺序固定为：主模型失败后调用备用模型；备用模型失败或未配置时执行本地兜底。单次请求最多尝试两个模型。

## 保存与校验

- 模型配置与业务路由分别保存，互不覆盖。
- 保存路由前检查主模型和备用模型是否启用、是否通过连通性测试。
- 存在不可用模型时阻止保存，并定位到风险行。
- API Key 留空表示保留原密钥；新建模型时 API Key 必填。
- 删除、停用模型前检查业务引用关系。

## 兼容与迁移

现有全局配置迁移为模型池中的首个默认模型；现有业务全部指向该模型作为主模型，保持升级前调用行为不变。环境变量继续作为数据库未配置时的兜底来源。

## 验收标准

- 可维护至少两个启用模型。
- 五条业务可独立配置主模型、备用模型和失败处理。
- 连通性失败模型不能用于新路由。
- 已被引用模型不能直接停用或删除。
- 升级后现有业务默认调用行为不变。
- API Key 不以明文返回或展示。
