# 患者端小程序整体视觉重绘设计

**日期：** 2026-07-17  
**状态：** 已完成两轮视觉确认，待主人审阅书面规格  
**目标工程：** `patient-uniapp`  
**视觉方向：** A · Art Design Pro 医生私域型

## 1. 目标与边界

在不接入后端、不改变现有 mock 数据结构和页面功能的前提下，重绘患者端小程序全部界面。新界面保留 Art Design Pro 的品牌蓝、清晰栅格、白色卡片和专业秩序，同时吸收参考图的雾蓝氛围背景、大圆角卡片、轻量标签、柔和渐变和更强的内容表现力。

本期成功标准：

1. 现有 11 个页面和四个 Tab 功能全部保留，导航行为不变。
2. 医生始终是第一信任锚点，AI 仅作为分诊、咨询和报告解读的辅助能力。
3. 首页、咨询、档案、我的形成清晰统一的主视觉；表单、文章、FAQ、回复页遵循同一设计系统。
4. 长辈模式在字号、触控尺寸、间距和信息密度上有明显变化。
5. 需要位图视觉的区域使用 Image 2 生成正式资产，不使用网络图片、占位图或图片内正文。
6. 微信小程序构建和 TypeScript 类型检查通过。

本期明确不做：真实 API、登录鉴权、短信验证、支付、真实报告识别、真实医生照片、多医生平台化、页面增删和业务流程重构。

## 2. 产品重心

采用主人确认的 A 方案：医生私域型。

- 首页首先展示主诊医生、科室、医院和团队服务关系。
- 在线咨询可以说明 AI 辅助分诊，但不能让 AI 名称压过医生团队。
- 档案、加号、住院和联络表均围绕该医生团队组织。
- 不引入参考图中的医生市场、服务搜索或平台型分类导航。

## 3. 视觉系统

### 3.1 色彩

- 主品牌色：`#5D87FF`
- 主品牌深色：`#456FD8`
- 辅助紫：`#756FEA`
- 医疗青绿：`#13DEB9`
- 页面底色：`#F4F7FB`
- 雾蓝背景：`#DFE9FF`
- 主文本：`#14213B`
- 次文本：`#6D7B94`
- 卡片：`#FFFFFF`
- 分割线：`#E8EDF5`

渐变仅用于页面氛围背景、医生/档案概览卡和主操作，不用于长段正文或所有卡片。避免紫粉霓虹、玻璃拟态过度叠加和低对比灰字。

### 3.2 圆角与阴影

- 主信息卡：20–24px
- 功能卡：16–20px
- 输入框与按钮：13–16px
- 标签：8px 或胶囊圆角
- 阴影：低透明蓝灰阴影，只用于医生卡、主操作卡和浮动输入区

不同层级使用不同圆角，避免所有元素都呈现相同的胶囊形态。

### 3.3 排版与间距

- 页面标题：22–26px，700–800 字重
- 卡片标题：16–18px，600–700 字重
- 正文：14–16px，行高 1.55–1.75
- 次要说明：12–13px，但颜色必须满足可读性
- 页面横向留白：16px
- 卡片内边距：14–18px
- 相邻区块间距：12–18px

### 3.4 动效

只使用有目的的轻动效：

- 页面和卡片 180–240ms 淡入/轻微上浮；
- 按钮与卡片按压缩放不低于 `0.98`；
- 加载状态使用低刺激脉冲或骨架；
- 长辈模式与减少动态效果场景不依赖动效表达状态。

## 4. 页面信息架构

### 4.1 首页 `pages/index/index`

顺序固定为：品牌栏 → 医生信任卡 → 快速服务 → 健康指引 → 次级功能组。

- 医生信任卡展示姓名、职称、科室、医院、团队关系和简短擅长。
- 快速服务采用 2×2 卡片：在线咨询、门诊加号、住院预约、我的档案。
- 在线咨询为唯一强渐变卡，其余使用白色卡片。
- 健康指引使用 Image 2 内容封面，但正文标题仍由原生文本渲染。
- 原有医院电话、医生风采、服务包、文章、联络表、回复和 FAQ 均保留在次级分组。

### 4.2 咨询 `pages/consult/index`

- 顶部展示“张明远医生团队 · AI 健康助手辅助”。
- 固定医疗安全提示，不与聊天气泡混合。
- 医生/助手气泡为白色，患者气泡为品牌蓝。
- 分诊结果使用低、中、高三级语义卡，不只靠颜色区分。
- 上传区增加 Image 2 报告拍摄引导视觉。
- 底部输入区采用大圆角浮动卡，保留文字输入、图片选择和发送。

### 4.3 档案 `pages/archive/index` 与健康记录 `pages/archive/health`

- 档案首页使用蓝紫概览卡展示患者、服务团队和三个关键数字。
- 联络表摘要与操作入口使用白卡片，不在同一页面重复渐变。
- 健康记录分类保留 2 列网格，但统一使用线性图标、分类色点和数量。
- 记录列表强化日期、类型和摘要层级。
- 空记录分类使用 Image 2 空状态插画，并提供返回全部记录的操作。

### 4.4 我的 `pages/mine/index`

- 顶部从简单标题升级为患者资产总览卡。
- 第一组：健康档案、查看回复、医患联络表。
- 第二组：长辈模式、常见问题、门诊时间。
- 页面底部提供隐私说明，保持医疗数据可信感。

### 4.5 三类表单 `pages/form/*`

- 统一为：页面标题 → 渐变说明头卡 → 白色表单卡 → 单独同意 → 主按钮。
- 可见 label、必填标记、选择状态和错误信息必须保留。
- 错误显示在字段附近，并可同时使用 Toast；不能只用 Toast。
- 提交成功使用成功状态卡或明确反馈，再执行返回。

### 4.6 文章、FAQ 与回复

- 文章详情使用 Image 2 医疗主题封面，标题和正文均使用原生文本。
- FAQ 使用独立问答卡和清晰展开状态，不依赖细分割线堆叠。
- 回复页增加查询说明、输入区域、加载状态、空状态和结果卡层级。

## 5. 组件与代码边界

保持现有工程结构，只增加直接服务于本次重绘的最小公共能力：

- `App.vue` / `uni.scss`：全局背景、排版、按钮、状态和动效基础类。
- `packages/patient-design/tokens.css/json`：更新并补充经批准的视觉令牌。
- `DoctorCard.vue`：医生信任卡。
- `CoreEntries.vue`：2×2 快速服务卡。
- `FnGroup.vue`：次级功能列表。
- `PatientForm.vue`：表单视觉、字段错误和提交反馈。
- `AppIcon.vue`：继续使用代码原生线性图标，不用 Image 2 生成小图标。

不创建通用组件库、不引入新 UI 框架、不为一次性布局增加抽象层。

## 6. Image 2 资产

生成并保存到 `patient-uniapp/src/static/visual/`：

1. `rehab-guide-cover.png`：骨科术后恢复健康内容封面；柔和蓝紫医疗编辑插画；无文字、无 Logo、无人脸特写。
2. `report-upload-guide.png`：手机平整拍摄检查报告的医疗教育插画；突出完整取景与清晰拍摄；无可识别患者信息、无正文文字。
3. `health-record-empty.png`：健康记录空状态插画；文件夹、医疗记录和轻量健康符号；无文字。

图片不承担按钮、导航、图标和正文信息。生成后检查主体、颜色、裁切安全区和小程序显示效果。

## 7. 状态与错误处理

- 全局 bootstrap：加载、错误、重试三态。
- 咨询：发送中禁止重复发送；失败消息保留在列表中并提供重试提示。
- 表单：必填、手机号、同意状态使用字段级提示。
- 档案/健康记录：加载失败显示页面内错误卡；无数据显示正式空状态。
- FAQ/文章：数据未加载时使用骨架或页面内加载状态。

本期不修改 mock API 契约，只改呈现层和必要的本地 UI 状态。

## 8. 无障碍与适老

- 普通模式触控目标不小于 44×44px。
- 长辈模式触控目标不小于 52×52px，正文不小于 18px。
- 颜色不是状态的唯一表达方式；分诊卡必须带文字标签。
- 输入框始终有可见 label。
- 图片提供用途相关的替代说明；装饰图可使用空说明。
- 文本不得烘焙进 Image 2 位图。
- 底部操作区适配安全区域。

## 9. 验证

1. `pnpm run type-check`
2. `pnpm run build:mp-weixin`
3. H5 或微信开发者工具逐页检查 11 个页面。
4. 检查 375px、430px 等常见宽度下无横向溢出。
5. 检查普通模式和长辈模式。
6. 检查加载、错误、空状态、表单校验和咨询发送中状态。
7. 对比三张批准的视觉稿，确认医生主体、蓝色系统、卡片层级和图片使用边界一致。

## 10. 页面验收清单

- 首页第一屏能识别医生、在线咨询和加号入口。
- 咨询页第一屏能识别服务主体、安全提示和输入区。
- 档案页能在三秒内理解患者、记录数和下一步入口。
- 我的页能直接进入档案、回复、联络表和长辈模式。
- 三类表单字段清晰、错误可定位、提交按钮突出。
- 文章封面、报告引导和空状态均使用已生成的 Image 2 正式资产。
- 所有页面视觉统一但不机械复制同一种卡片布局。
