# AI 自主判级（保留 L1–L6 含义）· 设计说明

**日期：** 2026-07-22  
**状态：** 已实现（2026-07-22；Step B / 方案 B1；Step A 门控已落地）  
**模型裁定：** 复用现有 `modelConfig` / 超时 / `TRIAGE_AI_DISABLED`；单独一条「只出 level」轻量调用（`classifyLevelLLM`），默认关 `AI_LEVEL_CLASSIFIER=1` 才启用。  

**前置：** Step A — 症状自述（「我肚子有点疼」）不再因缺「怎么办」被 L6 静默（`group_gate` sentinel / 部位+不适）。

---

## 1. 目标

在**不改 L1–L6 名称与业务含义**的前提下，重做「怎么判级」：

| 档 | 含义（保持不变） | 回复策略（与近期产品裁定对齐） |
|----|------------------|--------------------------------|
| L1 | 急症 / 高危 | 安全话术（120/当日就医），**不附**小程序贴片 |
| L2 | 需医生 | 可附贴片 + 转人工 |
| L3 | 需医助 | **建议文字**可自动发，不附贴片，需人工跟进 |
| L4 | 低风险 | **建议文字**可自动发，不附贴片 |
| L5 | 编号指令 | 编号快路径，照旧附卡 |
| L6 | 闲聊 | 静默 |

核心变化：收到消息后，由 **本地安全地板 + AI 判级策略** 产出档位，再按档位决定静默 / 建议 / 贴片 / 转人工；门控只挡噪音与真闲聊，不再用过严关键词替代分级。

---

## 2. 非目标

- 不改后台展示的 L1–L6 标签文案与筛选项名称  
- 不在本规格内重做运营配置中心 UI  
- 不取消急危「禁推线上问诊」策略（L1 仍不附卡）

## 3. 判级流水线（提议）

```
消息进入
  → 门控（噪音/真闲聊 → L6 静默；编号 → L5 快路径）
  → L1 本地地板（红旗/急症确定性，不可被 AI 降级）
  → AI 判级（输出 level∈{2,3,4} 或 medium/low + needsDoctor 信号）
  → 合并：rank 只升不降；L2 = medium∧需医生；L3 = medium∧需医助；L4 = low
  → 按档合成回复（贴片闸门 = 仅 L2 + L5）
```

### 3.1 门控（瘦身后）

放行：编号、菜单、业务意图、症状自述（sentinel / 部位+不适）、用药确认、@助手。  
静默：寒暄、无意义短句、纯天气等（L6）。  
**不再**要求「症状必须带怎么办」才放行（Step A 已满足）。

### 3.2 AI 判级职责

输入：患者原文、可选会话摘要、本地地板命中摘要。  
输出 JSON（示意）：

```json
{
  "level": 3,
  "riskLevel": "medium",
  "needsDoctor": false,
  "reason": "轻症自述，需医助跟进",
  "confidence": 0.7
}
```

约束：

- 若本地地板已 high → **不调用** AI 判级（L1）  
- AI 不得把地板 high 降为低档（机器钳制）  
- AI 失败 / 超时 → 回落现有 `scanRisk` + `classifyLevel`（fail-safe，偏转人工）

### 3.3 与现网模块关系

| 现网 | 调整方向 |
|------|----------|
| `group_gate` | 保持瘦身门控；不做细档 |
| `scanRisk` / 风险天网 | 保留为地板 + 回落；AI 判级为其上的策略层 |
| `classifyLevel` | 最终展示档仍由此（或薄封装）统一产出，供消息台筛选项 |
| Dialogue Agent | 以最终 `level` 驱动 `reply_advice` / 贴片闸门 |
| `canAttachMiniProgram` | 仍仅 L2 / L5 |
