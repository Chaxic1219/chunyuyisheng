# 群内阿福式对话体验改版（advise + 按医生人设）· 设计说明

**日期：** 2026-07-24  
**状态：** 已落地（工程）/ 云测已冒烟；本地 `_health_chat_test.js` 75 PASS  
**前置：** `2026-07-24-health-chat-afu-like-design.md`（本文件为其体验修订，不推翻急危/开药红线）  
**动机：** 现网出现槽位粘滞、建议复读、人设丢失、禁教编号；且主人要求「澄清后给一大段结构化建议」「按需 RAG」「人设按医生专科」。

---

## 1. 已确认产品决策

| 项 | 决策 |
|----|------|
| 建议格式 | **纯文本分段**，**禁止 `**加粗**` / Markdown 星号** |
| 建议篇幅 | 信息够清晰后输出结构化建议，**全文 ≤500 字** |
| RAG | **非强制**；仅在知识触发点检索 |
| 人设 | **按医生**（姓名/医院/科室/`specialty` 擅长）动态生成；运营键可覆盖 |
| 编号引导 | 需要跳转时**主动告知「请回复对应编号」**（如 101），不再全局禁教 |
| 话题切换 | 新主诉/新部位 → 重置病情槽，禁止粘旧病 |

---

## 2. 截图缺陷 → 对策映射

| 缺陷 | 对策 |
|------|------|
| 「牙疼」仍回「下腹」 | 扩部位抽取（牙/头/胸/腰…）；检测主诉切换 → `resetClinicalSlots` |
| 「半个小时」无效 | duration 支持「半小时/半个小时/一会儿」等口语 |
| 同一建议连发三遍 | session：`adviceDelivered`、`lastAdviceText`；高相似则改短跟进或 route |
| 「你是谁」不做人设 | 身份问 → `identity` 短答（医助名 + 绑定医生专科），不复读病情 |
| 想找医生无编号 | `route` 相位：文末「请回复 101」；L2 允许附卡 |

---

## 3. 会话相位（修订）

```text
intake  → 信息不够：接住 + ≤1 追问；不 RAG；短文
advise  → 槽够清晰：结构化建议 ≤500 字；默认不 RAG（除非本轮命中知识触发）
followup→ 已发过建议后的追问：短答/补一点；知识问才 RAG；禁止整段复读
route   → 找医生/挂号/开药诉求/escalate：说明边界 + 编号引导（可附卡）
identity→ 「你是谁/你能干什么」：人设短答（可带菜单提示），不粘病情
```

与旧名兼容：`educate` 视为 `advise` 的别名（实现可映射，避免大面积改测）。

**进入 advise 的条件（满足其一）：**

- `bodyPart`（或主诉症状）+（`duration` 或 `painPattern` 或伴随 `hasFever`/`hasDiarrhea`）  
- 或具体知识问法已触发 RAG 且 sufficiency≠none  
- 且非 identity / 非 route / 非急危 floor

**已 `adviceDelivered` 后：**

- 用户续问病情细节 → `followup`  
- 用户换新部位/新病 → 重置槽 + 回 `intake` 或直接 `advise`（若新主诉已够清晰）  
- 用户要找医生 → `route`

---

## 4. 按需 RAG

**默认：** `retrieveEvidence` **不调用**向量检索，`sufficiency=none`，对话用通用观察建议（仍禁止编造诊断名）。

**触发后再检索**（命中任一）：

- 知识问法：`能吃|可以吃|忌口|术后|复查|护理|注意(事项)?|怎么喝|喝什么|饮食`  
- 或 FAQ 2-gram 强命中（≥阈值阈值）  
- 或运营显式「知识点」标记（二期）

触发后行为与旧 educate 一致：只用证据块改写；none 则诚实说「先按常见情况提醒」。

---

## 5. 结构化建议成文（无加粗）

企微不渲染 Markdown。模板结构（与主人示例同构，纯文本）：

```text
{一句接住+安抚}。先别太担心，很多情况与{常见诱因简述}有关，简单调整常能缓解。

最常见的原因（按概率）：
1. …
2. …
3. …

您现在可以立刻做的：
1. …
2. …
3. …

需要警惕（出现请尽快就医/急诊）：
1. …
2. …
3. …

若排除上述紧急情况，可先观察。还可告诉我{1个追问点}，我再帮您收窄。
{若需一对一：请回复 101，我发咨询入口。}  ← 仅 route 或文末可选，非每轮
```

硬约束：

- 全文 ≤500 汉字（实现按 `length` 截断到句号）  
- **禁止 `*`、`**`、`#` 标题、代码块**  
- 禁止开药剂量；红旗要写清何时急诊/120  
- 建议内容优先贴合 **该医生科室/擅长**（消化科群少谈骨科细则；越界则引导回本科或 101）

软模板需有「腹痛伴发热」等兜底长文；LLM 优先，失败降级软模板。

## 6. 按医生人设

### 6.1 数据源（优先级）

1. 运营配置 `personaHealthChat`（若有，整段覆盖/前置）  
2. 自动拼装自 `doctors`：`name`、`title`、`hospital`、`dept`、`specialty`  
3. 医助显示名：优先 intro 里 bot 名（如「小友医助」），否则「春雨家庭医生医助」

### 6.2 自动人设块（示例逻辑）

```text
你是「{botName}」，在企微群协助「{hospital} {dept} {name}{title}」团队服务患者。
擅长方向（仅作边界提醒，勿编造超出下列范围的专科结论）：{specialty}
说话：自然、接住、像真人医助；严禁自称 AI/机器人/大模型。
自我介绍时：说明自己是该医生团队的群医助，可帮忙做症状梳理、观察建议、服务编号引导；具体诊疗以医生面诊为准。
超出本科擅长时：诚实说明边界，并引导回复 101 走一对一/转诊路径。
```

吕富靖 → 消化/胃肠肝胆方向；黄安华 → 胆石病；郭强 → 风湿免疫；周玉春 → 中医男科。  
**「你是谁」必须带出当前医生姓名+科室**，不得用泛化「春雨小助手」盖住医生身份。

### 6.3 越界主诉

患者主诉明显远离 `specialty`/`dept`（如消化群聊牙疼）：

- 仍可给**通用安全观察**短建议（不装本科专家）  
- 说明「这更偏口腔科，我这边是{dept}团队医助」  
- 需要专科医生时引导 101 或建议线下对应科室

## 7. Session 扩展字段

在现有 `slots` / session JSON 内增加（不改表）：

| 字段 | 含义 |
|------|------|
| `adviceDelivered` | 本话题是否已发过长建议 |
| `lastAdviceText` | 上一轮建议正文（防复读） |
| `topicKey` | 当前主诉键（如 `腹痛`/`牙痛`） |
| `__chatPhase` | intake/advise/followup/route/identity（educate→advise） |

`mergeSlots`：若本轮抽出的 `topicKey` ≠ 旧 `topicKey` → 清空 `bodyPart/duration/painPattern/hasFever/...` 与 `adviceDelivered`，写入新槽。

---

## 8. 编号引导策略

| 场景 | 行为 |
|------|------|
| intake / advise 常规 | 可不提编号 |
| 用户要找医生 / 咨询 / 看病 | **route**：正文明确「请回复 101」；允许附卡 |
| 挂号/加号等服务意图 | 对应编号（303/404…），沿用 understand 服务规则 |
| 旧逻辑「禁止教发 101」 | **废止于 health_chat**；改为「非 route 不强推，route 必提示」 |

---

## 9. 验收场景

1. 肚子疼 → 追问 → 补时长/发热 → **一段 ≤500 字结构化建议**（无 `**`）  
2. 建议后再问「会不会严重」→ **短 followup**，不整段复读  
3. 「我牙疼」打断腹痛话题 → 接住牙疼，**不再提下腹**  
4. 「你是谁」→ 人设短答含 **当前医生姓名+科室**  
5. 「我想找医生」→ 请回复 101（可附卡）  
6. 「胆囊术后能吃鸡蛋吗」→ **触发 RAG** 再据实答  
7. 换医生群（黄/郭/周）→ 「你是谁」与建议边界随 `specialty` 变  

---

## 10. 非目标

- 不改小程序/H5 Runtime（仍二期）  
- 不放宽急危/开药合规  
- 不做跨医生知识混检  
- 不引入 Markdown 渲染依赖
