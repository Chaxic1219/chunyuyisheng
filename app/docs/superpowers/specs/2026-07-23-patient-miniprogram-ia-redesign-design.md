## 1. 背景与目标

现有患者端 UniApp Demo 为 4 Tab（首页 / 咨询 / 档案 / 我的），首页堆叠医生名片、四宫格核心入口与多组功能列表，入口重复、主路径不清晰。

主人要求**重新规划页面与功能**，方向为**大幅精简**：只保留 1～2 条核心旅程，知识与服务申请降级；交付为**规划文档 + 随后改骨架**；**保留**后台与小程序现有设计语言。

### 1.1 成功标准

1. 本文档含完整页面地图、主流程、入口层级（P0 / P1 / P2）。
2. 骨架实施后：Tab 为 **首页 · 咨询 · 我的**；无「档案」Tab；**首页无医生名片**。
3. 主路径可点通：站内建档引导 → 咨询；首页待跟进摘要 → 查看回复。
4. 加号 / 住院 / 联络表 **仅**二级入口可达。
5. 邀请建档落地页 + 成功页有路由占位（可 mock）。
6. 视觉仍用现有 `@chunyu/patient-design` 与现网组件语言。

## 4. 主流程

### 4.1 建档 → 咨询

**路径 1 · 邀请链接**

```
打开邀请 → 问卷建档页 → 提交 → 成功页
→ CTA「去咨询」可选（不自动跳）
→ 之后可从首页/咨询 Tab 进入
```

**路径 2 · 站内引导**

```
未建档打开小程序 → 首页状态区「完善档案」
→ 档案填写页 → 完成后回首页
→ 主 CTA 变为「去咨询」
```

约定：

- 未建档可浏览首页二级知识。
- 点进咨询时：**轻提示**完善档案；骨架期**不硬拦**（仍可进咨询）。

### 4.2 咨询 → 跟进闭环

```
已建档 → 首页「待跟进」摘要 或 直接进咨询 Tab
→ 发消息 / 看回复
→ 跟进详情统一进「查看回复」
```

约定：首页只展示条数或最近一条摘要，点击进入回复列表；不在首页展开完整跟进时间线。

### 4.3 二级服务申请

加号 / 住院 / 联络表 **不**插入主流程强制步骤；仅从咨询「更多服务」或「我的」进入。

## 5. 分页功能说明

### 5.1 首页

- **状态区：** 未建档 →「完善档案」；已建档 →「待跟进 N」摘要（可点进回复列表）。
- **主 CTA：** 未建档 → 完善档案；已建档 → 去咨询（`switchTab`）。
- **二级折叠：** 门诊时间、FAQ、医院电话、饮食/手术须知等（按 bootstrap 内容有则显示）。
- **明确不做：** 医生名片大卡、核心四宫格堆砌、服务包弹窗作为主路径。

### 5.2 咨询

- 顶栏一行「某某医生团队」（轻量，非名片）。
- 聊天流、选图（最多 3）。
- 「更多服务」入口 → 加号 / 住院 / 联络表。
- 未建档进入：toast/条提示，不硬拦。

### 5.3 我的

- 身份摘要（姓名；未填则提示完善）。
- **P0：** 患者档案填写、健康记录、查看回复。
- **P2：** 加号 / 住院 / 联络表。
- **P1：** FAQ、门诊时间、医生风采（文章）。
- 长辈模式开关；隐私说明短文案。

### 5.4 邀请占位页

- 问卷字段对齐既有建档/邀请设计（见 `2026-07-20-patient-invite-link-design.md`）；骨架期可 mock 提交。
- 成功页：成功提示 +「去咨询」按钮；**默认不自动跳转咨询**。
