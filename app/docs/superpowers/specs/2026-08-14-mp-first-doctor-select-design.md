# 小程序首次选医生（绑手机之后）

**日期：** 2026-08-14  
**状态：** 已确认，待实现

## 目标

- 第一次进系统、后台无任何医生关系的患者：绑手机后进入「入驻医生库」选择页，选中后再完善档案。
- 网页/邀请等已在后台挂过医生的患者：绑手机后不出现选医生页，自动沿用最近绑定医生。
- 带来源 `doctorId`（邀请/分享/扫码）：不弹选医生页，直接挂该医生。
- 系统内已有切换医生能力保留（健康服务等）。

## 非目标

- 不改网页建档流程。
- 不做多医生确认页（已定：自动用最近一条）。
- 不强迫已绑定用户每次冷启动重选。

## 流程

```
需登录功能 → 静默登录 → 未绑手机则绑手机
→ 医生归属闸门：
   已有 patients 关系 → 最近绑定医生
   否则有来源 doctorId → 该医生
   否则 → pages/auth/select-doctor → 选中后继续
```

## 判定

绑手机时：

1. 按已验证手机号 / person 查跨医生 `patients`，按 `updated_at` 倒序。
2. 有记录 → 用最近医生挂接，`needsDoctorSelection=false`。
3. 无记录且请求带来源 `doctorId` → 用该医生。
4. 无记录且无来源 `doctorId` → 只完成手机绑定，会话可暂无 `doctor_id`，`needsDoctorSelection=true`；**禁止**用 bootstrap 默认医生冒充用户选择。

前端闸门（`ensureLogin` + 绑手机成功回调）：

- `needsDoctorSelection` 或无会话医生 → 跳转选医生页（除非来源医生可立即 silentLogin）。
- 否则放行原 `returnUrl`。

## 页面与接口

- 新页：`pages/auth/select-doctor`（列表 = 当前库中全部入驻医生，含 id/姓名/医院/科室）。
- 新接口：`GET /api/mp/settled-doctors`（需已绑手机；医生可尚未选定）。
- 绑手机请求：仅在有来源医生时传 `doctorId`，不传 bootstrap 默认 id。
- 健康服务切换医生逻辑不改。

## 验收

1. 全新用户无来源 → 绑号后出现选医生页 → 可选中并完善档案。
2. 网页已建档同号用户 → 绑号后不出现选医生页。
3. 带 `doctorId` 进入 → 不出现选医生页。
4. 健康服务仍可切换医生。
5. 已删种子医生（huang/guo）不在入驻列表。
