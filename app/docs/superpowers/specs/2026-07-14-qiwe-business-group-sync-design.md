# QiWe 业务群真实同步设计

## 目标

社群工作台只展示管理员选中的真实 QiWe 业务群，并以 QiWe 的群、成员、消息和发送回执作为生产事实来源。保留模拟入站和手工新增入口，但其数据明确标记为测试或手工数据，不进入真实生产统计。

## 数据流

1. 管理员点击“同步企微群”，服务端调用 QiWe 群分页和群详情接口，将真实群及成员幂等写入本地。
2. 同步得到的群默认不是业务群；管理员在群配置中显式选择“业务群”。
3. `/api/qiwe/callback` 收到群消息后，仅已选择的业务群进入社群归档、患者身份和分诊链路；其他群直接忽略。
4. 实时消息按 QiWe 消息唯一 ID 去重。历史消息补偿只归档，不触发回复。
5. 出站消息只有 QiWe 返回真实成功结果后才记为已发送。

## 数据边界

- `community_groups.data_source`：`qiwe`、`manual`、`simulation`。
- `community_groups.is_business`：只有 `qiwe + 1` 才属于生产业务群。
- `community_members.data_source`、`community_messages.data_source` 用于隔离真实与测试数据。
- 真实统计只计算已选业务群及其真实成员、真实消息和真实出站记录。
- 旧数据不删除；无法由 QiWe 对账的历史行保留但不计入真实统计。

## 错误处理

- QiWe 同步失败不覆盖现有数据，并将错误返回后台。
- 群详情失败时保留该群上次成功同步结果。
- 重复回调返回成功但不重复落库或生成回复。
- 非业务群消息不落患者和社群业务表、不触发 AI。

## 验证

- 单元测试覆盖来源隔离、真实统计、业务群门禁、回调映射和幂等同步。
- 本地使用伪造 QiWe API 响应验证群与成员同步，不访问生产凭据。
- 运行全部现有测试并检查 JavaScript 语法。
