# 周玉春群功能编号与按医生配置界面设计

**日期：** 2026-07-22  
**状态：** 已实现并部署（2026-07-22）；原生卡封面待对该短链企微采集后就绪。  
**范围：** 周玉春健康群编号回复（引导语 + 跳转/原生小程序贴片）补齐；按医生隔离；配置中心增强 + 新建编号总览页。吕富靖等其它医生配置保持不变。

## 1. 背景与目标

当前周玉春群发送 `101` 等编号时，仅有运营引导语，没有春雨医生小程序原生贴片（seed 曾因缺少主页短链故意将 `rules.responses` 留空）。现已提供主页短链：

`#小程序://春雨医生/LgKHxRiHTqKDfVp`

目标：

1. 在**特定医生群**发送编号时，只回复**该医生**的引导语与跳转/贴片（周群→周，吕群→吕）。
2. 按运营表配置周玉春本轮要做的编号（见 §3）；跳过明确不做的项。
3. 系统内提供方便设置的界面：配置中心增强 + 新建「群功能编号总览」。
4. **保留吕等原有信息与行为不变。**

## 2. 方案选择

采用 **方案 1**：种子 + DB 补丁写入周玉春全量本轮编号；配置中心增强；新建编号总览页；原生卡走现有 `qiwe_weapp_templates` + 同短链 hydrate。

不采用：仅运营发布不改 seed（难复现）；新建独立配置域重做模型（工期长、双轨风险）。

## 4. 架构与数据隔离

按「当前医生」读写，互不覆盖。

| 存储 | 用途 | 周玉春本轮 |
|------|------|------------|
| `ops_configs` domain=`scripts` | 引导语、欢迎语 | 核对表内文案；301 去掉暂无短链说明 |
| `rules.responses` | 卡/链载荷 | 101/102/301/909 写入 `mp`；其它保留 |
| `doctors.content.chunyuIntegration` | 主页短链等元数据 | 写入 `doctorHomeShortLink` 等 |
| `qiwe_weapp_templates` | 企微原生贴片 | 同 `source_short_link`（LgKHx）一组占位 + hydrate |

发送链路不变：

`engine.match(doctorId)` → `withConfiguredCodeScript` → `prepareDelivery` / `deliverReplyToQiwe`（模板就绪则 `sendWeapp`）。

隔离硬约束：

- DB 补丁仅匹配 `slug='zhouyuchun'`（或该医生 id）。
- 总览页、配置中心一律绑定顶栏当前医生。
- 不修改 `lvfujing` seed 块、吕 weapp 补丁、`LV_DOCX_SCRIPTS`。

## 5. 原生贴片就绪流程

1. 部署：规则写入 `mp` + 短链；`syncWeappTemplatesFromRules` / 补丁创建同组占位。
2. 新短链与吕 `5ujZ` **不同组**，不能拷贝吕封面三件套；需对该短链做一次企微采集（现有 capture 能力）。
3. 同组任一编号就绪后，`hydrateRelatedTemplates` 补齐 101/102/301/909。
4. 未就绪时：总览显示「待采集」；发送侧沿用现有降级（短链文本等）。本轮交付目标是采齐后稳定出原生贴片。

## 6. 界面

### 6.1 配置中心（增强）

- 话术域：继续维护 `groupWelcome`、`code101`…。
- 显式字段「医生主页短链」→ 写入 `content.chunyuIntegration.doctorHomeShortLink`；**发布时**同步当前医生 101/102/301/909 规则中 `mp.external.shortLink`（不触及其它医生）。
- `codes_cards`：别名/启用/卡片说明；话术正文仍以 scripts 为准。

### 6.2 新页「群功能编号总览」

- 数据随当前医生切换。
- 列：编号、功能名、引导语摘要、跳转类型（主页卡 / 医院链 / 问卷 / 仅文案）、原生卡状态（就绪 / 待采集 / 不适用）、快捷「编辑话术」。
- 以只读总览 + 状态灯为主；改内容跳配置中心或关键词规则，避免双写冲突。
- 侧栏挂在配置/运营附近。

- 818 无海报资源则只发文案。
- 909 无送心意页面级短链 → 主页卡入口。
- 本仓库无 git；设计文档落盘于 `app/docs/superpowers/specs/`，不强制提交。
