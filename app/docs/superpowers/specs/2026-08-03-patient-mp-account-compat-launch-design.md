## 1. 背景与决策

本地已完成患者小程序账号、邀请、私密凭证、AI 同意、数据申请等安全实现，但生产仍为旧后端。主人选择 **方案 C（恢复后端工作并准备联调上线）**，并确认约束 **B**：

1. 医生后台、社群、分诊、企微、公开 bootstrap/message 等**非本次小程序账号加固路径**行为相对当前生产保持可用，不因本包引入分诊/社群策略漂移。
2. **现有已绑定患者会话尽量不断**：部署本身不批量强制重登；会话轮换只在新登录 / 换绑 / 解绑时发生，并提供兼容窗口。

## 2. 目标与非目标

### 2.1 目标

1. 在不批量踢旧会话的前提下，交付账号安全能力并与小程序新包同窗发布。
2. 采用**外科手术发布**：只同步小程序账号相关切片，不整仓覆盖。
3. Schema 只加列加表；启动迁移不批量作废会话。
4. 私密上传、数据申请等新能力可上线；旧公开凭证可读兼容，orphan 只隔离不删。
5. 回滚路径明确：优先恢复现网连续可用。

### 2.2 非目标

- 不为 `npm test` 中 61 项分诊/社群策略失败去改急症等级或社群策略。
- 不在本次自动执行不可逆患者数据删除。
- 不自动删除 orphan 公开凭证。
- 无单独批准不执行生产写入、迁移、重启或部署。
- 不把本地相对生产的分诊/社群/Agent 行为差异带进本发布包。

## 3. 总体策略

**推荐做法：外科手术发布 + 会话兼容开关 + staging/副本演练。**

| 维度 | 策略 |
|---|---|
| 代码范围 | 只发 MP 账号相关文件；冻结禁止同步清单 |
| 会话 | `MP_SESSION_COMPAT=1` 默认开；新登录仍轮换 |
| 功能 | 新接口加表；旧主路径不断；同窗发小程序 |
| 就绪 | 私密目录问题只影响新凭证上传，不拖垮整站启动/核心 API |
| 门禁 | 切片清单、备份、副本迁移、冒烟、主人批准 |

## 4. 会话兼容（约束 B 核心）

当前本地 `readSessionWithoutTouch` 在每次鉴权时要求「该 OpenID 最新未撤销 token」。生产存在同一 OpenID 多会话；原样上线会立刻大面积 401，违反约束 B。

### 4.1 规则

1. **`MP_SESSION_COMPAT=1`（生产首发默认）**
   - 校验：token 存在、`revoked_at` 为空、未过期 → 通过
   - **不**做「必须是最新一条」判定
2. **新登录 / 换绑 / 解绑**仍调用 `revokeOpenidSessions`，再签发新 token
3. **`MP_SESSION_COMPAT=0`** 后恢复「仅最新未撤销 token」；关闭前需公告，建议多数用户自然重登后再关
4. **医生上下文**
   - 新登录：仍强制有效且 `active=1` 的 `doctorId`
   - 兼容期内存量会话只读：不因缺医生/停用医生在部署时批量作废
   - 写操作（上传、AI、数据申请、换绑）仍要求完整绑定身份
5. **迁移禁止**批量 `UPDATE mp_sessions SET revoked_at=...`

### 4.2 验收

| 场景 | 期望 |
|---|---|
| 部署后未重登 | 原有效 token 仍可用于原可用接口 |
| 用户重新登录 | 旧票失效，仅新票有效 |
| 换绑成功 | 旧票失效，新票带新身份 |
| 关闭兼容开关后 | 仅最新未撤销票有效 |

## 5. 功能面兼容

### 5.1 非小程序路径

- 发布集不含分诊/社群 Agent/急症策略本地差异。
- `/api/bootstrap`、管理端、企微回调以生产行为为基线回归。
- `/api/message`：兼容期不打断现网已在用的合法调用；对会冒用身份并写库的请求保持拒绝。更严收口与小程序新包、公告同步后再做。

### 5.2 邀请

- 已登录且手机号一致的 Bearer / 有效网页会话提交保持可用。
- 短信未配置不假装可用；堵住「未验证仅凭链接+手机号覆盖他人档案」。

### 5.3 凭证

- 新上传 → `PRIVATE_UPLOAD_DIR` + `mp_private_files`。
- 旧公开文件保持可读；orphan 哈希后隔离，不挂档、不自动删。
- `PRIVATE_UPLOAD_DIR` 异常：仅新凭证上传失败；**不得**导致整站无法启动或 bootstrap/登录/message/管理端不可用。  
  （相对当前把私密目录错误计入全局 `runtimeReadiness`/`assertRuntimeReady` 的实现，需拆成「核心就绪」与「凭证能力就绪」。）

### 5.4 AI

- 推荐后端与小程序**同维护窗**发布，避免匿名窗口长期分裂。
- 审计只存元数据；不改医生后台既有分诊入口。

### 5.5 数据申请

- 纯新增路由与表。
- 小程序对 `404` 应提示「暂不可用」，避免当成登录失败（同窗发布后作保险）。

### 5.6 短信

- 生产拒绝 demo/log；未配置则 `smsAvailable=false`。
- 小程序生产不恢复短信备用假入口。

## 6. 发布切片与回滚

### 6.1 切片原则

上线前产出：`生产基线包` + `本次可同步文件列表` + `sha256`。禁止整目录覆盖。

预期纳入（以与生产 diff 最终清单为准）：

- `app/mp_auth.js`、`app/routes/mp-auth.js`、`app/routes/mp-ai.js`
- `app/routes/patient-public.js`（替换前做生产行为对照）
- `app/db.js` 加表/加列迁移、`app/rate_limit.js`、`app/mp_runtime_config.js`、相关 `sms_*` / `wechat_mp.js` / `server_lifecycle.js`（若切片依赖）

明确禁止同步：本地相对生产发生行为漂移的分诊、社群 Agent、急症策略等文件（除非证明与生产一致）。

小程序生产包与后端同窗发布。

### 6.2 迁移与配置

1. SQLite 一致性备份（含 WAL/SHM），验证可恢复  
2. 备份副本上启动新代码，确认幂等迁移与 `PRAGMA integrity_check`  
3. 不批量作废会话  
4. `NODE_ENV=production`、`MP_SESSION_COMPAT=1`、`PRIVATE_UPLOAD_DIR=/var/lib/chunyu-doctor/private-uploads`（`0700`）  
5. orphan 隔离；收紧过宽文件权限  

### 6.3 发布顺序

```text
冻结非必要写入 → 备份代码+DB → 副本迁移演练通过
→ 维护窗停 PM2 → 只同步切片 → 写 env/目录
→ 启 PM2 → bootstrap/health/ready
→ 旧 token 冒烟 → 新登录/换绑/邀请/上传/AI/数据申请
→ 管理端+社群+message 冒烟
→ 发小程序新包 → 观察 30min
```

### 6.4 回滚

| 情况 | 动作 |
|---|---|
| 仅小程序异常 | 回退小程序包；后端可留 |
| 后端异常 | 恢复部署前代码包 + 部署前 DB 备份；已迁移库不给旧代码继续写 |
| 已有新私密文件 | 保留 `private-uploads` 快照对账 |

### 6.5 批准门槛

- [ ] 切片清单已定且不含分诊/社群策略漂移  
- [ ] `MP_SESSION_COMPAT=1` 写入发布配置  
- [ ] 新备份可恢复；副本迁移通过  
- [ ] 私密目录与权限就绪；orphan 隔离方案确认  
- [ ] 旧会话不强制重登冒烟用例写好  
- [ ] 主人单独批准本维护窗  

## 7. 实施前本地改动

1. `MP_SESSION_COMPAT` 与存量会话医生策略  
2. 私密上传就绪与核心就绪拆分  
3. `/api/message` 相对生产的兼容对照与收口  
4. 发布切片冻结文档（可同步 / 禁止同步 + sha256 流程）  
5. 小程序数据申请 404 友好提示  
6. 兼容开/关专项测试  
7. 工作区整目录快照（当前无 Git）

## 8. 成功标准

1. 部署后未重登用户：原有效会话仍可用于原主流程只读/既有能力。  
2. 医生后台、社群、bootstrap、message：与发布前一致可用。  
3. 新包：登录、微信绑号、换绑、邀请、私密上传、AI 同意、数据申请可用。  
4. 回滚在副本上验证过。  
5. 无单独批准则生产零写入。

## 9. 与既有设计的关系

- 2026-07-31 设计中的安全目标仍然有效。  
- 本设计**修正上线方式**：用兼容开关与外科手术发布满足约束 B，避免「最新 token 立即全局生效」和「整仓覆盖带上无关漂移」。  
- 关闭 `MP_SESSION_COMPAT` 视为**另一次**需批准的收紧操作，不包含在首发维护窗默认动作中。
